Integration Time and BLE API

How the active firmware adapts to low light, and how an external app can read and validate its BLE status record.

Low-light behaviour

Three UP integration levels

Both sensors use 3.7x gain. One six-channel exposure takes approximately 2 × 2.8 ms × (cycles + 1) because two channel banks are converted.

LevelProfileCyclesExposuresApprox. integration
1up_100x11001566 ms
2up_255x125511.434 s
3up_255x32553, summed4.301 s
  1. Capture level 1.
  2. If dark-corrected 810 nm is below 75 counts, discard it and capture level 2.
  3. If still below 75, discard it and capture level 3.
  4. Calibrate and calculate NDVI using only the final profile.
Level 3 adds three separate exposures; it does not average them. Each profile therefore requires matching calibration and dark-offset data.

DOWN sensor

Independent escalation

DOWN starts with down_255x1. If dark-corrected 645 nm or 810 nm is below 75 counts, it discards that result and captures down_255x3.

  • 255 × 1: approximately 1.434 s
  • 255 × 3 summed: approximately 4.301 s
  • Escalation depends on DOWN, not UP

Result quality

What LOW means

LOW=1 means at least one sensor remains below threshold after its final profile. NDVI is still calculated, but apps should label or reject it as low confidence.

Retries are cumulative. Reaching the longest UP and DOWN profiles requires about 12 seconds of sensor conversion time.

Discover by service UUID; the default name may be shared by several devices. A measurement must be started with the physical button or m over 115200-baud USB serial. BLE exposes the latest status only.

Wire format

Status payload

NDVI=0.67,SEQ=42,MS=183921,BAT=84,UP=1,DN=1,LOW=0,UI=255,UX=1,DX=1,SAT=0,CVM=31

The record is comma-separated KEY=VALUE text with no newline.

FieldMeaning
NDVILatest result, two decimal places, -1.00 to 1.00
SEQCompleted-measurement counter
MSDevice uptime in milliseconds at completion
BATEstimated battery percentage, 0 to 100
UP, DNSensor available when set to 1
LOWFinal signal remains below threshold
UISelected UP integration cycles: 100 or 255
UXSelected UP exposure count: 1 or 3
DXSelected DOWN exposure count: 1 or 3; cycles are always 255
SATBit 0 = UP saturation; bit 1 = DOWN saturation
CVMCalibration-valid profile bit mask

CVM bits 0–4 map to up_100x1, up_255x1, up_255x3, down_255x1, and down_255x3. A value of 31 marks all profiles valid.

App logic

Accepting a reading

  • Require SEQ > 0 and a new sequence number.
  • Require UP=1, DN=1, and LOW=0.
  • Require selected profile bits in CVM.
  • Require relevant SAT bits to be clear.
  • Store the full payload with the NDVI result.

Connection flow

Recommended sequence

  1. Scan using the service UUID.
  2. Connect and discover the status characteristic.
  3. Read once for initial state.
  4. Subscribe if the client supports notifications.
  5. Require every field and de-duplicate using SEQ.
  6. Repeat discovery after reconnecting.

Compatibility

Use reads as the authoritative transport

The record exceeds the 20-byte value available with the default ATT MTU. The current firmware does not explicitly request a larger local MTU or add a Client Characteristic Configuration Descriptor. Notification behaviour can therefore differ between BLE clients.

  • Use a characteristic read to obtain the full record.
  • If a notification is incomplete, discard it and perform a read.
  • Polling SEQ is the safest cross-platform fallback.
  • Ignore unknown keys, but require all documented keys.
The status has no wall-clock timestamp, unique device ID, or protocol version. Timestamp it in the app and associate it with the connected device.
